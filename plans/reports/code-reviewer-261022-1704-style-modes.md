# Code review: style modes (outline / filled / duotone)

Scope: uncommitted diff (scripts, schemas, docs) plus new consistency.py, variants.py. tests/integration/test_style_modes.py: 35 passed (49 s). Locked files (.claude/skills/icon-set-*, dependencies.lock.json): unmodified. Name collision: none (`common.guardrails`/`guardrails.json` vs `consistency.py`/`consistency_overrides`; "guardrails" appears only in the plan folder name).

## High
1. validate_icons.py:201-206 - duotone alpha check gives a false export error for every filled variant in a duotone set. It looks at the set's mode, not the icon's (`variant_of` is ignored). Repro: a resvg render of a solid currentColor rect has 0 pixels at alpha 74-80 at 16/24/32/48/64 px, so every exported variant PNG gets "no pixel at the secondary opacity 77/255". Reproduced.
2. validate_icons.py:201-206 + docs/SRS.md FR-QA-06 - the same check cannot reliably catch a dropped fill-opacity. Antialiased edges of an ordinary outline icon (no fill-opacity) already put pixels in the +/-3 band: 1 at 16 px, 1 at 24 px, 10 at 32 px, 0 at 48 px. FR-QA-06 ("a renderer that drops fill-opacity is detected") therefore overstates what the check does. Reproduced. Fix: measure the alpha of interior pixels (mode of the non-edge alpha, or a minimum pixel count), and skip icons that have `variant_of`.
3. consistency.py:139 - `float(raw)` on `fill-opacity="30%"` (allowed by SVG2/CSS) raises ValueError. check_svg does not catch it and run_main only maps ToolError/ImportError/OSError, so `validate_icons --phase source` dies with a traceback. Reproduced. The same applies to any non-numeric value (`fill-opacity="abc"`). Fix: parse the value (handle `%`), and report an unparsable value as a finding.
4. consistency.py:42-44, 93 + style-spec.schema.json `value: {}` - override values are never type-checked. `{"duotone-opacity-range": {"reason":"x","value":0.3}}` passes the schema, then fails with `TypeError: cannot unpack non-iterable float`. `{"stroke-min-at-smallest": {"value":"2"}}` fails with `TypeError '<' float vs str`. `[0.5, 0.2]` is accepted and makes every opacity an error, with a suggestion that cannot be satisfied. All reproduced; each crash is a raw traceback from `style_spec check/finalize` and from source QA. Fix: add per-rule value schemas (number, or a 2-item ascending array) or validate the values in `limit()` and raise ToolError(EXIT_INPUT).

## Medium
5. consistency.py:119-144 - fill-opacity set any way other than the attribute is not seen. `style="fill-opacity:0.3"` (the inline-style regex in validate_icons.py:63 only matches `fill:`/`stroke:`) and `opacity="0.3"` both give a duotone master a false "no secondary layer" error. In outline mode the same partly transparent fill passes with no warning at all. Reproduced. Fix: read `style` declarations and `opacity` (multiplied down through ancestors), or reject both forms in source QA.
6. manifest.py:161 and duplicate_check.py:44 - `ic["variant_kind"]` raises KeyError when a hand-edited entry has `variant_of` but no `variant_kind`. The inventory schema does not tie the two fields together, and no caller validates the inventory on load. duplicate_check is reproduced (`KeyError 'variant_kind'`); manifest is the same pattern, found by reading the code. Fix: add a `dependentRequired` in the schema and use `.get(..., "filled")`.
7. validate_icons.py:91-101, 151-155 - `variant_of` is trusted without checks. validate_source loads inventory.json with plain load_json (no schema check), so the kebab pattern on `variant_of` is never enforced there:
   - `"variant_of": "../../../x"` reads and renders `masters/../../../x.svg` from outside the set. There is no ensure_inside or symlink check on the base path. Found by reading the code.
   - Self-reference (`variant_of` = own id) passes: the box is compared with itself, so drift is 0 (reproduced via variant_findings).
   - A cycle (a->b, b->a) or a chain of variants is not rejected.
   - Any of these turns an outline icon into a "filled" one and removes its upstream envelope warning, so hand edits can get around mode-matches-spec.
   Fix: in validate_source, require `variant_of` to be an inventory id other than the icon's own, whose own entry has no `variant_of`, and apply the kebab pattern before building paths.
8. consistency.py:128-144 - a shape with no `fill` anywhere in its ancestors is painted black. It is neither recorded as a fill nor reported, so a filled master with one fill-less path passes source QA (reproduced). The exported mean-colour check only catches it later. Fix: in filled/duotone mode, flag drawables whose resolved fill is None.

## Low
9. consistency.py:105-109 - `duotone-secondary-contrast` is always a warning, even when `style_mode` is declared. Criterion 4 / FR-SPC-05 say a declared mode means errors; the plan says "warning, then error after calibration". Either the code or the docs should say which applies.
10. consistency.py:71-76 - the suggestion can give 1.0, which the schema forbids (exclusiveMaximum 1), or a value outside the 0.2-0.5 range rule, so following one finding causes another.
11. style_spec.py:114 - `duotone_secondary_opacity` is part of geometry_hash, so an opacity-only edit invalidates approvals/exports as a geometry change. The geometry_hash docstring says "palette-only edits leave it unchanged". This is defensible, but intent should be stated. Criterion 1 holds: outline specs (no mode, or an explicit "outline") hash the same, as the pinned tests confirm.

Not issues (verified): preview escapes `variant_of`, `form` and ids through escape_html. `href="#..."` cannot become `javascript:`. form_rules interpolates only schema-enum values, because load_spec validates the spec. variants.py rejects a variant of a variant. A fully transparent render returns None bounds and produces a finding, not a crash.
